# 数据回流与自我进化

本文件定义收到真实视频数据后的自动复盘流程，以及如何把结论沉淀到经验库。

## 触发条件

用户回传任意真实数据（如：抖音播放1万，完播率20%，点赞200），或要求复盘某条视频时，立即执行本流程。`@投放数据`优先级高于普通自然语言复盘，并立即挂起常规生成。

## 硬边界

- 不调用平台数据分析API；数据由用户手动提供。
- 缺失数据不推测成确定值，标注【待补充】。
- 只做数据可支撑的归因，不写“感觉”“应该是”这类模糊结论。

## 必算指标

| 指标 | 计算方式 | 判断标准 |
|---|---|---|
| 前3秒留人率 | 前3秒留存人数 ÷ 播放量 | 低于30%判定钩子不行，下次必须重写开头。 |
| 互动率 | (点赞+评论+收藏+分享) ÷ 播放量 | 低于3%判定情绪共鸣不够，下次必须强化共鸣、争议或提问。 |
| 完播率 | 看完人数 ÷ 播放量 | 与同平台、同赛道历史水平比较；不设固定及格线。 |
| 最大流失时段 | 留存曲线中下降幅度最大的相邻时间区间 | 写出具体时间码，如 00:07-00:12。 |

## 自动分析步骤

1. **归一数据**：把用户给出的原始数据整理成平台、赛道、主题、发布时间、播放量、前3秒留人率、完播率、点赞、评论、收藏、分享、最大流失时段。
2. **判断钩子**：先算前3秒留人率；低于30%时直接判定开头失败，不得归因为“平台不给量”。
3. **投后硬锚点**：完播率<15%判定开场前3秒钩子失效；点赞率>3%判定情绪共鸣或价值点有效并保留结构；评论率>1%判定互动引导有效。缺失指标标【待补充】，不用估算值替代。
4. **定位流失**：有留存曲线或分段数据时，找出最大流失时间段；没有时标注【待补充：分段留存数据缺失】。
5. **判断共鸣**：计算点赞率、评论率和互动率；点赞率低于1%且评论率低于1%时，检查情绪曲线是否太平、结尾是否缺具体提问、评论区引导是否太泛。
6. **提出动作**：把问题翻译成下一支视频的可执行修改，例如“第1秒改成手部特写+一句反常识结论”，不写“提高开头吸引力”。
7. **更新经验库**：把结论按SKILL.md的【微调库写入】规则追加到 [feedback-library.md](../feedback-library.md)，同时可在 [case-study.md](case-study.md) 留下核心数据与动作摘要。

## 自我进化规则

- 同类问题重复出现2次，升级为硬禁令，写入经验库的“下次必须避免”。
- 成功钩子可以复用结构，但不照抄台词和文案。
- 生成新视频前必须读取 [feedback-library.md](../feedback-library.md) 的投放数据记录和 [case-study.md](case-study.md)，优先检索真实数据沉淀，再检查是否踩中已记录的失败模式。
- 新视频交付时不复述复盘过程，但选题、钩子、节奏和互动引导必须体现经验库修正。
