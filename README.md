# video-pipeline

简体中文 | [English](README.en.md)

短视频一条龙脚本引擎。从选题策划、分镜脚本、视频生成提示词、封面图提示词到多平台发布包、数据复盘的完整工作流。

**定位**：[脚本引擎] —— 只输出脚本、分镜、提示词与发布包，不产出视频文件。生视频由用户在即梦、可灵、Sora 等工具中手动完成。

---

## 完整流程总览

```
触发（常规生成 / 快捷预设 / 链接复刻 / @投放数据 / @复盘）
    │
    ▼
启动检查：workspace续写/开新片；读 SKILL.md + model-limits.yaml；按命中规则懒加载
    │
    ▼
确认流：推荐赛道 → 挂起；确认主题 → 挂起；选配确认单（含模型/平台）→ 挂起
    │                                                            │
    └── 用户回复"按推荐来"或参数后一次性生成 1-4 步 + 已确认平台包 ◄──┘
    │
    ▼
阶段落盘 workspace.md
    │
    ▼
用户手动生视频/剪辑；如平台未确认或需调整，走第5步平台兜底确认
    │
    ▼  视频发布后
投后校准：@投放数据 回传真实数据 → 作废自评 → 数据诊断 → 更新微调库 → 下一轮同赛道优先读取
```

## 用户操作流程

| 阶段 | 用户做什么 | 技能做什么 |
|---|---|---|
| 1. 提需求 | 输入主题、赛道、链接或预设词 | 检查 workspace，按需加载规则，开始确认流 |
| 2. 确认赛道 | 选择推荐赛道，或输入自定义赛道 | 推荐候选后挂起，禁止擅自决定 |
| 3. 确认主题 | 选择推荐主题，或输入自定义主题 | 推荐候选后挂起 |
| 4. 确认参数 | 回复"按推荐来"，或自定义时长/画幅/风格/模型/平台 | 输出【选配确认单】并挂起 |
| 5. 一次性生成 | 确认后等待完整交付 | 输出选题、分镜、所选模型提示词、封面、评分卡和已确认平台包 |
| 6. 手动制作 | 把提示词复制到即梦/可灵/Sora，完成生成和剪辑 | 不调用生视频 API，不产出视频文件 |
| 7. 补平台包 | 如平台未确认或需调整，回复"剪完了"或指定平台 | 先给平台优先级建议，确认后只输出指定平台包 |
| 8. 投后复盘 | 回复 `@投放数据 播放量=... 完播率=...` | 作废 AI 自评，用真实数据诊断并写入微调库 |

想减少确认轮次时，输入 `确认流=极速`：赛道、主题和选配参数合并为一张确认单，但仍必须等用户确认后才能生成。

## 一、装载逻辑（启动阶段）

启动只读 `SKILL.md` 和 `config/model-limits.yaml`，其余文件按命中规则懒加载。固定装载顺序：


## 二、四步确认流与选题策划

**触发**：`做一条【类型/赛道】，主题是【XXX】`。类型可省略，技能按 [references/track-routing.md](references/track-routing.md) 匹配候选赛道，但只用于推荐，不静默替换用户选择。

确认顺序固定：

1. **第一步：确认赛道**。未指定赛道时输出 2-3 个候选并标星首选，每个附一句理由，末尾提示可自定义；输出后立即挂起。
2. **第二步：确认主题**。赛道确认后输出 3 个候选主题并标星推荐，末尾提示可自定义；输出后立即挂起。
3. **第三步：选配确认单**。逐项输出时长、画幅、风格、主角身份、生成模型和目标平台，每一项都提供推荐和自定义入口；输出后立即挂起。生成模型默认推荐 Seedance 2.5，用户可通过 `模型=全部` 显式选择三套。
4. **第四步：生成**。只有收到用户选择的参数、"确认"或"按推荐来"后才恢复；随后一次性输出以下 1-4 步成果。选配确认单中的目标平台一旦被用户确认，平台包随本次生成一并输出；生成模型同样以确认单为准，未经确认不得切换。

**输出内容**：

1. 主选题 1 个 + 备选 1 个，每个含：选题名、切入角度、一句话钩子、首发重点（1-3 个优先平台）、形式建议（口播/记录/混剪/剧情）、与热点关联。
2. 热点词必须来自用户输入（`热点词=A,B,C`）；未提供时选题开头标注 `[需手动填入热点词]` 留占位，禁止虚构。
3. 赛道重叠时输出重叠警告和候选赛道，由用户确认；禁止静默路由。

首发平台只影响第 5 步的平台优先级建议，不代替用户确认。

## 三、第2步：分镜脚本

固定 7 列表格：`镜号 | 时间码 | 画面（含花字） | 台词 | 音效 | 时长 | 钩子与情绪`。

**黄金 3 秒法则**：第 1 秒视觉冲击或悬念抛出；第 2-3 秒痛点直击或反常识结论；3 秒留不住人直接重写脚本。

**黄金节奏表**：

| 时间段 | 节拍任务 | 情绪目标 |
|---|---|---|
| 0-3 秒 | 钩子 | 好奇/焦虑/紧张 |
| 3-10 秒 | 痛点放大或背景交代 | 焦虑/共鸣/期待 |
| 10-25 秒 | 转折点或核心冲突（情绪峰值） | 紧张/爽感 |
| 25-40 秒 | 解决方案或情绪升华 | 爽感/释然 |
| 最后 5 秒 | 金句收尾 + 强互动引导 | 共鸣/期待 |

总时长不是 40 秒时按同一节拍压缩或延展，但 0-3 秒钩子、峰值段和最后 5 秒收尾不可缺失。

镜头数量：15 秒用 4-6 镜，30 秒用 5-8 镜，60 秒用 8-12 镜；时间码连续不重叠不缺秒；禁止连续三镜同一情绪。

有真人主体时，分镜表之后紧跟输出一次 `[CHARACTER_CARD]`（性别、年龄段、发型、面部特征锁定、服装、配饰、关键道具），拆段生成时完整注入每一段，并附带角色一致性降级策略。

## 四、第3步：视频生成提示词（参数化编译）

由 `模型=` 参数控制输出：

| 参数 | 输出 |
|---|---|
| （默认）/ `模型=seedance` | 豆包 Seedance 2.5，1 个代码块 |
| `模型=seedance2.0` | 豆包 Seedance 2.0，1 个代码块 |
| `模型=hailuo` | MiniMax Hailuo 3，1 个代码块 |
| `模型=全部` | 三套，3 个代码块 |

画幅固定默认 9:16，仅用户明确要求时输出 16:9。

**固定叙事链**（每条片强制套用，每个模型代码块首行必须写 `[固定叙事链]` 逐节点映射）：

```
现实压力锚点 → 幻想种子 → 微缩奇观 → 触发物穿越 → 主体登场 → 动作证明 → 收口 → 现实回声
```

非奇幻赛道（口播带货、种草）只替换节点内容不删节点；`节点=口播` 压缩为【钩子+痛点/价值证明+行动呼吁】；极简模式（≤15秒+低密度+单场景）压缩为【吸引注意+核心展示+行动呼吁】。

**导演台模式**：只写可观察的动作、可拍摄的环境和有原因的运镜，禁止"科技感""高级感""电影感"等空洞词。

**超时长拆段**：段数 = CEILING(目标时长 / 模型单段上限)，具体上限以 `config/model-limits.yaml` 为准。每段用滑动窗口携带上下文：`[故事大纲]`+`[上一段末尾状态]`+`[当前段目标]`，不带入全部历史段落。

## 五、第4步：封面图提示词

一套，画幅与视频一致。优先选择变形、反转、峰值、产品与痛点反差或目的地震撼画面。

## 六、阶段落盘

第 1-4 步结束时强制写入 `workspace.md`（若已存在则创建 `workspace-<片名>.md`），包含：选题策划、7 列分镜表、CHARACTER_CARD（如有）、按所选模型保留的提示词代码块、封面提示词、自查评分卡。

第 5 步只读 workspace 文件 + 规则文件，禁止携带前 4 步历史对话全文，大幅降低多轮对话 Token 消耗。

## 七、平台发布包兜底（分层默认）

**触发**：平台名单未在第三步确认，或用户事后要求追加、调整平台时说 `剪完了`。执行"先推荐、再确认、后输出"：

1. 输出一行 `[平台优先级建议]`（例如：建议主发抖音+小红书，辅发B站/视频号；出海补充TikTok/YouTube）。
2. 询问用户确认平台名单（默认建议主流3：抖音、小红书、视频号）。
3. 用户明确回复平台列表或输入指令后才生成代码块。未经确认禁止输出任何平台包，禁止一次性输出全平台。

平台指令：

| 指令 | 输出 |
|---|---|
| `平台=主流3` | 抖音、小红书、视频号 |
| `平台=出海` | TikTok、Instagram、Facebook、YouTube、Threads、X、Pinterest |
| `平台=全量` | 全部 14 个平台 |
| `平台=抖音,B站` | 只出指定平台 |

每个平台一个独立代码块，使用紧凑字段行：`标题 / 话题 / 标签 / SEO关键词 / 封面文案 / 互动引导 / 预埋评论2条 / 最佳发布时间`。标题按"悬念+痛点+结果承诺"公式；预埋评论必须引用具体镜号或台词；禁止复述剧情、重复分镜或提示词。发布包全文先过敏感词库过滤。

**最终输出** = 用户确认的平台包 + `[自查评分卡]`（钩子得分、信息密度得分、情绪价值得分等，判定必须引用具体镜头号和台词证据）。

## 九、链接逆向复刻（6 步）

**触发**：`复刻这个链接：[链接]`。只复刻结构、节奏、镜头、光影、情绪和互动逻辑，不照搬人物、台词、品牌和专有内容。

1. **处理链接与素材分级**：A级（原片文件/可逐帧链接）完整复刻；B级（完整关键帧+字幕+时长）可复刻但缺项标【待补充】；C级（只有链接/标题/简介/封面）进入【爆款结构逆向工程】模式，输出开头钩子、情绪曲线、叙事节奏、核心爆点、结尾引导五维骨架表，确认后用全新主题、台词和画面重构脚本。本地原片先运行 `scripts/replication_frames.ps1` 生成每秒帧索引。
2. **原片秒级拉片**：从 00:00 到最后 1 秒建立秒级台账，每一秒单独一行，禁止跳秒、缺秒或写"同上"；再合并出镜头/节拍块表。
3. **逐秒映射**：原片每一秒对应新片每一秒，保留镜序、节奏、钩子位置、转场位置和情绪峰谷；压缩时长时先输出秒级压缩对照表。
4. **复刻提示词**：按 `模型=` 参数输出（与常规生成同一套路由），按逐秒映射表写，超上限自动拆段。
5. **复刻脚本**：固定 9 列（新片秒/时间码/原片秒/原片镜号/画面/台词/音效/时长/钩子与情绪）。
6. **平台确认与发布包**：同第 5 步分层默认流程，必须等用户确认平台后才输出。

无原片时，所有骨架判断必须标【推断】；技能只使用链接元数据和用户补充描述，禁止假装已看原片。用户后续补齐原片或完整关键帧+字幕后，可切换为逐秒对位复刻。

复刻流程同样执行阶段落盘：第 1-5 步成果写入 workspace，第 6 步只读 workspace + 规则文件。

## 十、投后数据校准与数据复盘

**触发**：`@投放数据 播放量=5000 完播率=25% 点赞=300 评论=20`。收到指令后技能挂起常规生成，进入数据校准模式。数据由用户手动提供，缺失数据标【待补充】。

投后校准规则：

| 指标 | 硬锚点 |
|---|---|
| 完播率 | <15% 判定开场前3秒钩子失效，下一轮必须重写第1-3秒 |
| 点赞率 | >3% 判定情绪共鸣或价值点有效，保留该结构 |
| 评论率 | >1% 判定互动引导有效，保留评论区钩子和结尾提问 |
| 前3秒留人率 | 用户给出分段数据时校准；否则标【待补充：前3秒留存】 |

每次输出：`①本次数据诊断`、`②评分卡修正`、`③微调库写入`。真实投放数据会作废此前AI自评评分卡；微调库按赛道保留最近5条，同一坑重复2次升级为硬禁令。技能后续生成同赛道脚本时，优先检索 `feedback-library.md` 中的真实数据沉淀。

`@复盘`继续用于主观反馈和满意结构沉淀；`@投放数据`用于可量化的发布后校准。

普通复盘必算指标：

| 指标 | 判断标准 |
|---|---|
| 前3秒留人率 | 低于 30% 判定钩子失败，下次重写开头 |
| 互动率 | 低于 3% 判定共鸣不够，强化共鸣/争议/提问 |
| 完播率 | 与同平台同赛道历史水平比较 |
| 最大流失时段 | 写出具体时间码，如 00:07-00:12 |

分析结论写入 `feedback-library.md`（同赛道只保留最近 5 条）和 `case-study.md`。同类问题重复出现 2 次升级为硬禁令。下一轮生成时，每段提示词在 `[约束]` 前自动注入 `[上轮修正]` 修正词，直到用户输入 `@复盘 满意` 才移除。

## 十一、辅助脚本

**敏感词扫描**（发布前手动复核）：

```powershell
powershell -File scripts\scan_sensitive_words.ps1 -Path <要扫描的文件.md>
```

命中输出 `[SENSITIVE_HIT]` 和逐行明细；通过输出 `[SENSITIVE_SCAN] PASS`。词库在 `references/sensitive-words.md`，可用 `-ListPath` 指定自定义词库。

**链接复刻抽帧**：`scripts/replication_frames.ps1` 用 ffprobe 读取总时长、抽每秒帧、生成 `per_second_index.csv` 和 10 秒接触表。

**模型过期提醒**：当前日期距 `config/model-limits.yaml` 适配日期超过 60 天时，技能第一行追加 `[提醒] 模型参数已超60天未更新，请核实`。
